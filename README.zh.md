# Folder Nav

[English](README.md) · **简体中文**

一个 Obsidian 插件,把侧栏的文件树换成**逐层进入**的浏览方式 —— 侧栏一次只显示当前文件夹的内容,顶部面包屑带你往回走。就像在 Windows 资源管理器或 macOS Finder 里双击进入文件夹。

再也不用看着层层缩进把窄侧栏的宽度啃光。

## 为什么

Obsidian 自带的文件列表每一层都往里缩进。到了第三、四层 —— `笔记 › 课程 › 第三周 › 讲义.pdf` —— 文件名已经被挤成一条缝,而且整棵树永远摊在屏幕上跟你抢注意力。

Folder Nav 让侧栏的层级深度恒定:你看见的是自己正站着的那个文件夹,面包屑告诉你它在哪。

## 用法

默认开启:它会接管自带的**文件列表**视图。侧栏标签页没变,左侧图标栏的那个按钮也照常工作。

**鼠标**

| 操作 | 结果 |
| --- | --- |
| 点文件夹 | 进入该文件夹 |
| 点文件 | 在**主编辑区**打开(绝不会占用侧栏) |
| 点面包屑上的任意一段 | 跳回那一层 |
| 点 `←` | 返回上一级 |
| 右键文件或文件夹 | **新建笔记** / **新建文件夹**、**重命名**、**移动文件夹到…**、**创建副本**、**删除** —— 以及其他插件贡献的菜单项 |

> Obsidian 的核心右键菜单项是**文件列表自己的代码**在触发 `file-menu` 事件**之前**加进去的,所以监听这个事件的插件只能拿到第三方贡献项。Folder Nav 既然替换了那个视图,就得用公开 API 把这些核心项重建出来。其中**删除**直接交给 Obsidian 自己的 `promptForDeletion`,所以你的「删除前确认」设置是生效的。

**键盘**(先点一下列表)

| 键 | 作用 |
| --- | --- |
| `↑` / `↓` | 移动选中 |
| `Enter` | 打开选中项 |
| `Backspace` / `Alt+←` / `Cmd/Ctrl+[` | 返回上一级 |
| `Esc` | 取消选中 |

**命令**(也可以在 设置 → 快捷键 里自行绑定)

- `Folder Nav: 切换逐层导航 / 原生文件列表`
- `Folder Nav: 回到库根目录`
- `Folder Nav: 返回上一级文件夹`
- `Folder Nav: 定位到当前文件`

## 文件夹颜色

给文件夹指定一个颜色,它会延续到下面所有层级:该文件夹所在的那一行染上底色,进去之后整个侧栏背景也染上同一个色。逐层导航看不到父层,颜色就是"你现在在哪"的依据。

<p align="center">
  <img src="assets/demo-root.png" width="300" alt="染色的文件夹行">
  <img src="assets/demo-nested.png" width="300" alt="进入后整片背景洗色">
</p>

**设置颜色** —— 右键任意文件夹 → **文件夹颜色**,点一个色块即可。自己没有颜色的文件夹会**继承最近的上级颜色**,所以往更深层走也不会丢掉提示。

**管理颜色** —— 设置 → Folder Nav → 文件夹颜色 会列出所有已上色的文件夹,旁边有「背景染色强度」滑块。设为 `0` 时只染文件夹那一行,列表背景不动。

颜色一律是**半透明叠在你主题自己的背景之上**,从不改动前景色 —— 所以文字清晰度完全由你的主题决定,不会因为染色而看不清。

## 设置

| 项 | 说明 |
| --- | --- |
| **背景染色强度** | 进入已上色文件夹时背景染色的浓度,数值就是透明度百分比。`0` 只染文件夹那一行。 |
| **接管文件列表** | 关掉立刻恢复原生树,不留任何痕迹。 |
| **排序方式** | *跟随原生* 套用接管时内置文件列表正在用的排序(字母序、修改时间等);*文件夹优先* 始终把文件夹排在文件前面,再按名称排。 |
| **自动定位当前文件** | 切换笔记时自动跳到它所在的文件夹。初始值取自 Obsidian 自己的「自动显示当前文件」设置。 |
| **显示文件扩展名** | 关掉后 `笔记.md` 显示为 `笔记`。 |
| **在库根目录隐藏散落文件** | 只影响库的根目录 —— 附件在根目录堆积时很好用。 |
| **隐藏的扩展名** | 逗号分隔,配合上一项使用。 |

## 工作原理

Folder Nav 替换的是文件列表 **leaf 里的那个视图**,而不是禁用 Obsidian 内置的文件列表插件。禁用那个插件会连带移除左侧图标栏的按钮,而且要去操作它就得碰未公开接口。本插件**全程只使用公开的工作区 API** —— 没有用到 `app.internalPlugins` 或任何私有接口。

替换会在 `layout-change` 时重新执行,所以内置插件重建自己的 leaf(布局恢复时,或你手动运行「打开文件列表」)也不会让原生树冒出来。重复的逐层视图会被收敛成一个。

插件**不会改写你库里的任何配置** —— `workspace.json` 和 `core-plugins.json` 从头到尾没被碰过。

## 已知限制

- **不能拖拽移动文件。** Obsidian 原生的拖拽绑定在它自己的文件列表内部实现上,复用它就意味着依赖未公开接口。请用右键菜单的**「移动文件夹到…」**,它会打开一个文件夹选择器。
- **没有 F2 原地重命名,也不支持多选。** **重命名**在右键菜单里,会弹一个小对话框。一次只能选一个文件。
- **不还原自定义文件夹顺序。** 排序是算法算出来的,而不是向内置文件列表借的 —— 那个视图在接管时已经被销毁了。你用别的插件拖拽排过序的文件夹,这里会按名称或日期排。
- **Obsidian 自带的「在文件列表中显示当前文件」在接管期间不起作用。** 它操作的是内置文件列表的视图,而那个视图已经不在加载状态,所以它会安静地什么都不做 —— 不会多开一个文件列表,也不会报错。请改用 **Folder Nav: 定位到当前文件**,如果你给原命令绑了快捷键,改绑到这个上。
- **Obsidian 大版本更新后仍可能需要修。** 接管基于公开的工作区 API,但它毕竟替换了一个核心视图,而没有任何 API 承诺这件事永远有效。失效时的表现是安全的:接管跑不起来,你就拿回原生的文件列表。
- **桌面和移动端。** `isDesktopOnly` 是关的,但逐层布局主要在桌面上验证过。

## 开发

```bash
npm install
npm run build     # 类型检查 + 打包
npm run dev       # 监听模式
```

`main.js` 输出在项目根目录。开发时想顺便复制进某个库:

```bash
OBSIDIAN_PLUGIN_DIR=~/MyVault/.obsidian/plugins/folder-nav npm run build
```

如果你装了 Obsidian CLI,调试闭环是这样:

```bash
obsidian vault=MyVault plugin:reload id=folder-nav
obsidian vault=MyVault dev:errors
obsidian vault=MyVault dev:screenshot path=/tmp/shot.png
```

### 源码结构

```
src/
├── main.ts       插件入口:生命周期、命令、设置接线
├── view.ts       FolderNavView —— 导航状态、历史栈、列表渲染
├── takeover.ts   把内置文件列表的视图换成我们的,以及换回去
├── breadcrumb.ts 面包屑路径构建
├── render.ts     单个列表行
├── palette.ts    文件夹调色板与就近继承查找
├── colorPicker.ts 取色弹窗
├── sort.ts       排序与库根目录过滤
└── settings.ts   设置页
```
